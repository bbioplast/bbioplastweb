# Code audit — 15 October 2026

Baseline: main commit `8ddb6c4f21052c822f6cf99ee06b812885322d34`.
Scope: existing Node/SQLite storefront, quotation workflow, admin authentication, imports, CMS, media, and HTTP delivery. No schema migration or replacement backend is required.

## Fixed findings

| Area | Finding and correction |
| --- | --- |
| Authentication | An in-flight login could create a session after a password change revoked sessions. Recheck the stored password hash inside the session transaction. Concurrent password changes also reject stale credentials instead of overwriting the newer password. |
| API validation | JSON null/primitive/array bodies could cause internal errors. Reject unsupported bodies and content types with a controlled client error. |
| Products/imports | Manual writes and import commit used inconsistent case matching for SKUs. Use consistent Unicode case matching, detect intervening duplicate SKUs, and preserve existing legacy records. Import header aliases reject inherited object property names. |
| CMS text | Editing text removed inline typography and icons. Replace the changed text range while preserving existing markup and unchanged line breaks. |
| Media | Invalid metadata could leave an unregistered file that blocked a later upload. Validate before writing and recover registration of an existing same-hash file. Local image paths reject dot segments. |
| Admin navigation | Slow responses from an earlier screen could replace the newly selected screen. Guard asynchronous loaders and error handling against stale navigation. |
| Blog | Retry after a failed list request lost the required listing controls. Restore the published template before binding filters again. |
| Cart | Rapid quantity clicks could be dropped or overwrite another tab's changes. Queue actions and resolve relative quantity changes inside the storage lock. |
| Checkout | Failed submission could re-enable submit despite an empty/unavailable cart. Re-evaluate readiness after failure. |
| HTTP | Stream errors could be unhandled; large assets were fully buffered. Handle request/stream failures and stream large files. |

## Performance and cleanup

- Rendered public HTML is cached with bounded size and invalidated by both same-connection SQLite writes and external-connection data versions. Drafts remain unpublished; withdrawn details and redirects are checked before cache lookup.
- Avoid a duplicate source read and skip the first CMS DOM parse when all section values, order, and visibility are unchanged.
- Brotli/gzip representations are reused. Static assets support ETag/Last-Modified revalidation; HTML and private APIs retain browser `no-store`.
- Catalog search text, category counts, sort order, and cart lookups are indexed once per catalog load.
- Import commit builds one current SKU/version map instead of scanning the table for each row.
- A single syntax-check script covers application, browser, scripts, and test JavaScript. Local npm cache is ignored.

Local HTTP benchmark: five warmups followed by 50 sequential requests per page, Node 24, isolated seeded SQLite database. These are local server timings, not production page-load or network timings.

| Route | Baseline mean | Updated mean | Baseline HTML transferred | Updated Brotli transferred |
| --- | ---: | ---: | ---: | ---: |
| `/` | 15.56 ms | 1.09 ms | 22,245 bytes | 4,672 bytes |
| `/products` | 5.53 ms | 0.87 ms | 8,755 bytes | 2,738 bytes |
| `/works` | 8.56 ms | 0.81 ms | 16,181 bytes | 3,697 bytes |

CSS transfer: 20,171 to 5,459 bytes; repeated conditional request returns 304 with zero body bytes.
An isolated import commit benchmark (5,000 existing products, 1,500 updates, median of three runs) reduced lookup/write time from 364.2 to 26.6 ms; parsing and network are excluded.

## Limits

This is a code review and regression pass, not a penetration-test certification. Reverse-proxy client IP trust was not changed without a verified proxy contract; current rate limiting still keys on the socket address. External image/font availability and real-user network performance remain dependent on their providers. Local performance figures should be remeasured against production traffic before capacity planning.

Run `npm run check`, `npm test`, and `npm run benchmark` with Node 24. In a sandbox that blocks test subprocesses, use `node --test --test-isolation=none tests/*.test.js`.
